- [stack] API in Python 3.14 + FastAPI in `api/` (task allows only Java 21+/Python 3.14+ and requires REST + Docker); Next.js stays only as the optional frontend
- [stack] No Supabase/Vercel/DB (task bans external SaaS/APIs and storing files; nothing needs persistence)
- [ai] Default provider: Eden AI (`deepinfra/deepseek-ai/DeepSeek-V4.1-Flash-1017`), also in the delivered solution. Chosen 2026-11-22 after a test of 6 open-weight models on form 9 (the hardest) and the winner on forms 1-8: fewest places to fill in left without a field, no made-up statements, no repetition loop on any form, 3-24 s and under 0.005 USD per form (Qwen3-VL-30B-A3B, the model before: 1-7 min, loops, made-up statements; Qwen3.5-397B close but 9x the cost; Qwen3.6-35B and Qwen3.5-122B always reason first, which cannot be switched off through Eden, and the 122B used its whole limit on it; Mistral-Small-4-119B returned invalid JSON). Open weights, MIT (`deepseek-ai/DeepSeek-V4.1-Flash-1017`), a 552B MoE with 8B active: runs on a GPU server, not a laptop. Offline option: local Ollama, `qwen3-vl:8b` (Apache-2.0, reads text and scans; small = cheap to deploy). Answer limit 12000 tokens (form 9 needed ~7.6k and hit 8000)
- [ai] Eden AI (organizer-provided) is the only external AI provider, open-weight models only (same model must run locally); no Anthropic API (task rules). Chosen with `AUTOFORMULARZ_LLM_PROVIDER=eden` (plain httpx, no SDK). `docker-compose.yml` runs the API on Eden by default (`ollama` and `model` only with `--profile ollama` and `AUTOFORMULARZ_LLM_PROVIDER=ollama`); the eden overlay file is gone. Key only in `api`. Cost per call in `llm.EDEN_USAGE` (results reports, total since start in `/health`); extra seams: `llm.before_eden_call` (can block a call) and `llm.usage_hooks` (token usage per paid response). Dev pair: `deepinfra/Qwen/Qwen3-VL-30B-A3B-Instruct` ↔ `qwen3-vl:30b` (Eden has no Qwen3-VL 8B)
- [ai] LLM fills a small FormSpec (constrained by JSON Schema); a deterministic compiler builds the COI JSON (long JSON with UUIDs/jsonata from a small model is unreliable; code is testable and repeatable)
- [ai] Predefined sections (office, applicant, address, proxy, stamp duty, contact, consent, preview) come from compiler templates, not the model (standard says use them; same techNames and queries as reference JSON)
- [format] Follow the reference JSON where it differs from the written schema: `repeatingSectionGrid` (not `repetingSectionGrid`), also for plain SECTION; address/contact prefilled from MLPZ but editable
- [format] FINISH page may hold INFO_SECTION and TEXT_BLOCK (agreed with COI mentors; reference 5 uses TEXT_BLOCK), no warning
- [format] Verbatim source text only for instructions and legal basis (TEXT_BLOCK sections on the FINISH page); statements stay short and gender-neutral from the model, the GDPR clause is only linked (design standard, "Oświadczenie"). OFF by default (`AUTOFORMULARZ_COPY_SOURCE_TEXT=false`): on the saved results the model marked paper instructions, the request text and the GDPR clause as INSTRUCTION/LEGAL_BASIS; turn on once roles are reliable (e.g. checked in code)
- [ai] Presort (`presort.py`, `AUTOFORMULARZ_PRESORT`, on): code recognises the GDPR clause, paper-only lines (signature, date, "wypełnia urząd", fill-in instructions, page footers) and the applicant/address/contact data the compiler adds from the template; those blocks are left out of the prompt and their roles added after the model (fewer input and output tokens, fewer role errors). Rules on normalised text (no diacritics, no numbering) so wording may vary; when unsure the block goes to the model. Hand-written lines (`……`, `____`) are shortened to `……` in the prompt only. Runs of ≥6 blocks identical to an earlier run (later versions of a multi-version request, form 9) are shortened to a note "dalej bloki … takie same jak …", so the model describes the common part once; form 8's short repeats (rate tables E.1/E.2) stay. Measured on the materials: form 8 prompt −30%, form 9 −57%, forms 1 and 7 −60–80%
- [ai] A looping answer is not an error: Ollama streams the answer and generation stops when the model writes 2 sections in a row that it already wrote (same title and fields, as in the canon); an answer cut at the limit (Eden, or Ollama at `llm_max_tokens`) is salvaged too: its complete pages/sections up to the loop are used, with a note in the result, no second call. A single repeated section is normal (form 9: the same "Opinia" on two pages) and never stops the answer; checked on all saved results
- [ai] Versions of one request (form 9): when the canon drops a copy of a section, it merges the copies' `show_if` (union over the options; not expressible as one condition = always shown), and a section whose source blocks repeat in another version (shortened by presort) is shown for that version too. Before, the model's per-version copies collapsed to the first one and the "Nagroda" form was empty
- [ai] Ollama `keep_alive` 30m (`AUTOFORMULARZ_LLM_KEEP_ALIVE`, Ollama's default 5m): the next form does not reload the model and reuses the cached system prompt
- [format] Consents (`consents`, CONSENT_SECTION as the design standard requires) are required, except a consent to be contacted by e-mail/phone/electronic delivery (the contact data are optional, so it cannot block sending); paper references like "wskazanego w poz. 71" are removed from their text
- [lint] Field order for condition checks comes from grid `y`/`x`, not the JSON array order (reference files store fields out of display order)
- [format] Element ids are UUIDv5 from form title + path (same input gives the same JSON, readable diffs)
- [format] `validation` lists REQUIRED + validators (PESEL, NIP, REGON, ZIP_CODE, EMAIL...); validators also inferred from labels (reference leaves it empty; validation is an extra-points item)
- [extract] DOCX read from XML incl. text boxes (forms 2 and 8 are built from text boxes); .ods read natively from its XML (same output as the LibreOffice path on all 9 materials); only binary .doc via LibreOffice headless (MPL-2.0 external process, not linked, nothing of ours to publish; mentors: allowed only with such a license, be careful); scanned PDF pages rendered with pypdfium2 (PyMuPDF is AGPL)
- [extract] Scans: tall images of stacked pages are cut into A4 pages at blank rows; OCR with Tesseract + `pol` (Apache-2.0, separate process, stdin, one thread) gives the same Document blocks as text files, page images still go to the model (OCR misses empty tick boxes). Deterministic, ~1 s/page, 87-100% word recall vs DOCX on the materials; without Tesseract scans go as images only
- [upload] `.doc` and `.docx` are one format ("DOC (.doc .docx)" in the task): the content decides how it is read (materials 5 and 7 are DOCX named .DOC)
- [api] Contract for parallel work: `extract` returns a `Document` (blocks `b1…` + field candidates), FormSpec points to block IDs (`blocks`, `block_roles`), `?details=true` adds `document` and `coverage` (model classifies, code keeps the text; see docs/pipeline.md "Kontrakt")
- [api] `POST /api/v1/forms` returns the importable JSON as-is; `?details=true` adds FormSpec, lint issues and notes for the UI
- [api] Progress via polled jobs: `POST /api/v1/jobs` returns 202 + id, `GET /api/v1/jobs/{id}` gives the steps so far (pipeline stages, then title/page/section/field names read from the streamed model answer) and the result, `DELETE` cancels (the stream closes, the model stops). Jobs only in process memory, dropped 15 min after the last change, max 4 running. Reason: one long request hit fetch's 5-minute header timeout in the Next proxy; progress costs no tokens (no extra model calls, Eden streams with `stream_options.include_usage`). `POST /api/v1/forms` stays synchronous for other clients
- [api] JWT HS256 with shared secret from env; `AUTOFORMULARZ_AUTH_ENABLED=false` only for local dev
- [docker] Debian slim, not Alpine (LibreOffice and PDF/imaging wheels need glibc); LibreOffice optional via build arg
- [tooling] Biome (not ESLint/Prettier); ruff + pytest via uv for `api/` and `scripts/`; lefthook git hooks
- [tooling] Slides in Marp (`docs/prezentacja.md` → PDF via `npm run slides`, MIT, run with npx, not a dependency): versioned with the code, theme modeled on COI visual identity (Behance board in `materialy/inspo_prezentacja`, coi.gov.pl): conic-gradient circles and squares as on coi.gov.pl, Inter Light, navy #04122f, magenta gradient #871c6c→#e10a58, blue #133692, no COI logo
- [git] No AI attribution in commits/PRs (team rule): disabled in .claude/settings.json, blocked by lefthook commit-msg hook
- [ui] Design system for forms in `src/components/form` (fields 1:1 with JSON `field.type`), gov.pl-like tokens + Lato; see docs/design-system.md
- [ui] Renderer `CoiFormView` (`src/components/form/coi-form.tsx`) builds the e-form from COI JSON, not from hand-written forms; `states` evaluated with the `jsonata` package (MIT) on a copy of the JSON with `__userAnswer` injected (exact syntax from "Reguły techniczne", incl. `$repeatingSectionIndex`), so any query from the compiler or the reference files works; preview at `/podglad`
- [ui] Start page `/` uploads the file through the Next route `/api/forms`, which signs a short-lived JWT with `AUTOFORMULARZ_JWT_SECRET` (node:crypto, no new dependency) and forwards to `POST /api/v1/forms?details=true`; the secret and API address never reach the browser
- [ui] `CoiFormView`: values written in the JSON are shown (office name, "Polska"), registry data (`EXTERNAL_SYSTEM`) is not invented: a read-only field of that kind says it is filled from login data. "Dalej" checks the page as the e-service does (stays with an error summary linking to the fields; format checked on leaving a field, a cleared required field too); the stepper opens only pages already reached. Labels as in the COI visualisation of material 1: required fields have no marker, optional ones "(opcjonalnie)" (none for read-only fields and fields with a "Brak …" checkbox); no asterisks
- [ui] JSON `description` HTML is converted to React through an allowlist (no innerHTML, inline styles dropped, so only design-system tokens)
- [ui] Biome linter off for `src/components/ui/**` (generated shadcn code, kept as upstream); still formatted
- [ui] Start page is a 3-step flow (file → creating → check) with the form `Stepper`; AI output marked with the EU icon for AI-generated content (AI Act art. 50 Code of Practice, free use, `src/components/form/ai-icon.tsx`): no official COI or mObywatel AI icon found
- [ui] Length limits set by the renderer (COI JSON has no length setting; task 3.3.VI "długość pola"): by validator (PESEL 11, NIP 13, REGON 14, kod pocztowy 6, e-mail 254), a fixed-digit `pattern` (KRS 10), phone 20, other text 255 (as the form title in "Reguły"), TEXTAREA 2000, NUMBER 15; a "12 / 255 znaków" counter shows while typing and once filled, warning colour and a screen-reader message in the last 10% of free text (limit 50+; a full PESEL or postcode is complete, not a warning); the counter appears once the field has a value (shown on focus it vanished on blur and shifted the page under a click). Navigation buttons keep the focus on mouse down for the same reason: a field's blur check shifted the layout and "Dalej" missed the click. A phone field (no COI validator) is recognised by its techName/label and gets the phone check and keyboard; NUMBER is a text field with a numeric keyboard and a number check (a browser `type="number"` hides invalid input)
- [ui] Safety scan of the generated form (`src/lib/form/safety.ts`, no dependency): requests for passwords/PIN/SMS codes/card data, links outside gov.pl or without HTTPS, text addressed to a model (prompt injection, EN and PL), hidden zero-width/bidi characters, HTML/script, labels over 200 characters. It warns (list in the check step, confirmation before "Pobierz JSON") and never changes the JSON; no false alarms on wyniki 2-9
- [ui] The check step shows the generated JSON (task 3.3.IV "przeglądanie wyjściowej struktury danych"): "Podgląd e-formularza / JSON" switch, coloured with design tokens, copy button; file name checked in the browser too (250 characters, no `; : > < / \ | ' * % $`, as the API)
- [extract] DOCX footnotes and endnotes: Word draws their marks, so the text lost "(nr telefonu/adres e-mail)1)"; references get their numbers (order of first use) and the notes' text comes at the end ("1) Dane nieobowiązkowe."), as on paper. Only material 1 changes
- [ai] Presort also takes footnotes the e-form covers by itself (how to sign; "dane nieobowiązkowe" when its marks are found, also per spreadsheet cell; OCR's "2]"), with their continuation lines; the hand-written line of a removed bracket label ("……" over "(podpis wnioskodawcy)"); "(data)"; and in a two-column letter header it gives the model only the addressee (right column) while the left label still tells that a company may apply ("nazwa wnioskodawcy"). Form 1 now reads the same in PDF, DOCX, DOC, ODS and XLSX
- [ai] After the model (presort.apply, code knowledge only): a footnote "dane nieobowiązkowe" decides `required` (marked field optional, the rest of the source text required unless conditional); a field made only of blocks the code recognised (paper-only, GDPR, template applicant data) is dropped; a field on a line with no place for it (no place to fill in, or more fields than places) stays only if its label shares a word with the line (form 1: "Numer budynku" as a third field of a two-place line). The model's own SKIP roles are not trusted for this (form 6: it gave SKIP to the contractor's phone). Checked on wyniki 2-9: no real field lost
- [ai] A model stuck repeating one field inside a section (same label and source blocks a 3rd time; table rows with one label point to other blocks) is stopped while streaming, Eden and Ollama alike, and the answer is cut before the repeats and closed (`field_loop`, `close_json`). Form 1 had "Numer porządkowy" 22 times and ran to the 12000-token limit (~7 min)
- [format] Canon: a copy of a section under another title (same fields and source blocks) or a shorter copy without its own condition is dropped; a one-option choice or a field whose label restates the form title is dropped. Preview section uses TEXT_BLOCK `podglad_1` (design standard "pole typu blok tekstu", references 1 and 5). "Numer PESEL" in "Twoje dane" and "Dane innej osoby" only when the paper asks for a PESEL (presort, outside the GDPR clause): the design standard lists it, but both COI references follow the paper (material 1 and its visualisation have none, material 5 has it)
- [ai] Prompt: a field is a place to fill in on the paper with its label, in the paper's order; the title and the request sentence ("Wnoszę o…") are not fields, nor what the office will issue; one request has no "Rodzaj wniosku"
- [ui] Preview draws what the COI platform adds to address fields (no key in the import format): "Brak nazwy ulicy" under "Ulica", "Brak numeru lokalu" under "Numer lokalu", "Brak kodu pocztowego" for a postcode abroad (design standard "Wyświetl dodatkowy checkbox wyłączający pole"; ticking it clears and skips the field); a short "Np. …" description becomes the placeholder and a postcode gets "__-___", as in the visualisation of material 1
- [ui] The consent's link to the information clause (`#klauzula-informacyjna`: the compiler cannot know the office's BIP address) opens a dialog with the clause read from the uploaded document (its GDPR blocks from `?details=true`); without a document it says the office publishes it. The clause stays off the form (design standard); clicking the link does not tick the consent
- [ai] The model writes `consents` (and `summary`, `signed`) before `pages`: after the pages they were lost whenever the answer was cut, and the model turned statements into TAK/NIE fields. A streamed answer stops when its last 2 complete sections are template or paper-only ones ("Dane kontaktowe", "Podpis", "Data", "Podgląd", "Zgoda na przetwarzanie"; `check.TEMPLATE_TITLE`): the form's own sections are done (form 2: 3600 instead of 11225 characters); the canon drops signature, preview, date and GDPR-consent sections (`check.PLATFORM_TITLE`), the compiler and the platform add them
- [extract] OCR in two passes: Tesseract `--psm 4` (one column, keeps form rows) drops the words after a long dotted leader, so a `--psm 11` (sparse text) pass adds what it found and the first pass did not: into the same row after "……" (a place to fill in), or as a new row in place; a row read a little differently by both passes is not doubled, words below confidence 60 or without 3 letters are ignored. Scan of material 1 now reads "w miejscowości …… przy ulicy" and "nr ewidencyjny działki …… w obrębie" like the PDF; form 9's table labels and form 3's "inne" come back. OCR takes about twice as long (form 9: 11 -> 20 s). OCR's reading of a raised "1)" as a closing quote counts as the mark of a single "dane nieobowiązkowe" footnote
- [ai] Statements the model writes stay only when most of their words occur in the document (the prompt's example "Dane w formularzu są zgodne z prawdą" appeared on forms without statements); a choice field that repeats a statement already among the consents is dropped (form 7 had them twice, the field's condition pointing to itself)
- [ai] Best of N (`AUTOFORMULARZ_LLM_SAMPLES`, default 1 for the live API): the model answers N times (the first at temperature 0, the others at `llm_sample_temperature` 0.4) and `pipeline.score` keeps the answer with the fewest lint errors, then the fewest places to fill in left without a field, then the fewest elements the canon dropped, then the most fields
- [format] A statement the paper itself makes conditional is optional: 4 consecutive lines hold most of its words and "dotyczy wyłącznie/tylko", "jeżeli" or "jeśli" (form 8, D.4 compost bin: "dotyczy wyłącznie właścicieli…", "zaznaczają kratkę, jeżeli…"); GDPR blocks are blanked so a window never joins lines apart on paper. Set by presort (`FormSpec.optional_consents`, hidden from the model); on wyniki 2-9 only form 8's compost statement changes. Prompt: words split by a slash with a "niepotrzebne skreślić" mark ("wynajem/użyczenie*") are a single choice (form 4). The best-of-N score counts statements with fields
- [results] wyniki 2-9 on DeepSeek V4.1 Flash, best of 3 (forms 8 and 9 best of 5): 0 lint errors, 0-5 places left without a field (form 9: 66, three requests in one with repeated parts). Form 9 keeps the answer with the conditions per kind of request (16) over one with more fields but none of them conditional; it lacks the club representative's and proxy's own sections
